# Монитор мест Ticketon

Команда `/kino` открывает inline-клавиатуру с фильмами из раздела [«Кино» Ticketon для Астаны](https://ticketon.kz/astana/cinema) и кинотеатрами города. Список наблюдения и настройки общие для чата: любой участник может включить или выключить фильм, фильтр кинотеатра, минимальное время начала сеанса и требуемое количество соседних мест. `✅` означает, что пункт уже выбран. Если кинотеатры не выбраны, проверяются все кинотеатры Астаны; если время не задано, подходят сеансы в любое время суток. Кнопка `🔎 Проверить сейчас` запускает проверку только для текущего чата и возвращает все найденные сеансы одним сообщением.

Сервис передаёт каталогу Ticketon фильтры `city=astana` и `category=cinema`, а затем повторно проверяет главную категорию каждого результата. События из разделов концертов, театров, спорта и других категорий в меню и scheduler не попадают.

## Компоненты

- `src/kino/client.js` читает публичные JSON API Ticketon и нормализует фильмы, сеансы, сектора и места;
- `src/kino/seats.js` ищет последовательные свободные места;
- `src/kino/service.js` строит меню, переключает подписки и запускает проверки;
- `src/worker/index.js` запускает scheduler только в постоянном worker;
- `migrations/007_ticketon_cinema_monitor.sql` создаёт отдельные Ticketon-подписки;
- `migrations/008_ticketon_daily_digests.sql` создаёт суточные markers утреннего дайджеста;
- `migrations/009_ticketon_chat_preferences.sql` хранит настройки каждого чата;
- `migrations/010_ticketon_adjacent_seats.sql` добавляет выбранный размер соседнего блока.

Ticketon IDs не смешиваются с сохранёнными IDs прежнего провайдера: после миграции фильмы и кинотеатры нужно выбрать заново через `/kino`. Каталог меню кешируется в памяти worker на пять минут. Клавиатура разбивается на страницы по восемь пунктов, а выбранные позиции, исчезнувшие из текущей афиши, всё равно показываются, чтобы их можно было удалить.

## Проверка мест и утренний дайджест

Scheduler запускается сразу при старте worker, затем просыпается раз в `TICKETON_CHECK_INTERVAL_MS` (по умолчанию один час). До локального часа `TICKETON_DAILY_CHECK_HOUR` он ничего не загружает. Первый tick после этого часа проверяет выбранные фильмы на ближайшие семь дней, исключает прошедшие, закрытые для продажи и, если задан фильтр, чужие кинотеатры. За один суточный запуск и чат обрабатывается не более `TICKETON_MAX_SESSIONS_PER_RUN` подходящих сеансов.

Все найденные сеансы собираются в один компактный утренний дайджест с датой, временем, кинотеатром, залом, рядом, местами и прямой ссылкой на схему. Сообщение явно группируется по фильму, внутри фильма — по кинотеатру, затем по времени сеанса; варианты с полностью одинаковыми ключами идут по фактическому количеству соседних мест от большего к меньшему. Один и тот же доступный сеанс может снова попасть в дайджест следующего дня, если места всё ещё свободны. Если подходящих мест нет, автоматическое сообщение не отправляется. PostgreSQL marker `(chat_id, digest_date)` гарантирует не более одной автоматической обработки чата за локальный день; при ошибке отправки marker удаляется и следующий tick повторяет попытку.

Если Ticketon сообщает минимальную цену сеанса строго выше 5000 KZT, вариант получает строку `💸 Дорогой билет: от N ₸`. При цене ровно 5000 ₸ индикатора нет. Публичная карта мест отдаёт ID тарифа без его суммы, поэтому порог применяется к `min_price` сеанса: отметка означает, что даже самый дешёвый билет на этот сеанс дороже 5000 ₸.

Ручная проверка использует те же правила поиска, не меняет суточный marker и всегда отвечает одним сообщением: со списком сеансов либо с сообщением, что подходящих мест нет. Один ручной запуск читает не более `TICKETON_MANUAL_MAX_SESSIONS` карт зала и выполняется в heavy-очереди worker.

Кнопка `🕒 Время` задаёт нижнюю границу начала сеанса с точностью до часа: от 10:00 до 23:00 либо `любое время`. Например, при выборе `с 18:00` сеансы в 17:59 и раньше отбрасываются до загрузки карты зала, а сеансы ровно в 18:00 и позже проверяются. Фильтр применяется одинаково к ручной проверке и автоматическому дайджесту и показывается в итоговом сообщении.

Кнопка `💺 Мест рядом` задаёт минимальный непрерывный блок от 1 до 6 свободных кресел. Настройка применяется к ручной и автоматической проверке и показывается в дайджесте. Значение по умолчанию берётся из `TICKETON_ADJACENT_SEATS`.

Клиент соединяет статическую геометрию сектора с динамическим наличием по ID места. Свободным считается место с `count > 0`; сектора без нумерованных мест пропускаются. Ряды всех ценовых секторов сначала объединяются и сортируются по числовому номеру, а при текстовой метке — по координате `y`. Только после этого выбирается половина всего зала с более высокими номерами рядов, включая средний ряд в зале с нечётным числом рядов. Поэтому передний ценовой сектор больше не может ошибочно определить собственную «верхнюю половину». Среди блоков не меньше выбранного порога сервис возвращает самый большой непрерывный блок без пропусков номеров и большого физического разрыва по координатам карты.

Дайджест отправляется обычным Telegram-сообщением без тегов и упоминаний участников чата. Если найденных сеансов слишком много, в конце единственного сообщения показывается число не поместившихся результатов.

## Доступ к карте зала

Афиша, сеансы, геометрия зала и динамическое наличие мест читаются через публичные read-only endpoints `api-gw.ticketon.kz`. Клиент не отправляет `Authorization`, bearer-токен или cookie. Для мониторинга не нужно хранить пользовательскую сессию Ticketon.

## Настройки

| Переменная | Default | Назначение |
| --- | --- | --- |
| `TICKETON_MONITOR_ENABLED` | `true` | `false` отключает scheduler, не удаляя подписки |
| `TICKETON_BASE_URL` | `https://ticketon.kz` | Базовый адрес ссылок в уведомлениях |
| `TICKETON_API_URL` | `https://api-gw.ticketon.kz` | Базовый адрес публичного JSON API |
| `TICKETON_CITY_ID` | `1` | ID Астаны в API сеансов |
| `TICKETON_CITY_CODE` | `astana` | Код Астаны в каталоге и фильтре кинотеатров |
| `TICKETON_TIME_ZONE` | `Asia/Almaty` | Локальная дата афиши и отсечение прошедших сеансов |
| `TICKETON_CHECK_INTERVAL_MS` | `3600000` | Интервал пробуждения scheduler, минимум 60 секунд |
| `TICKETON_DAILY_CHECK_HOUR` | `9` | Первый локальный час утреннего дайджеста, от 0 до 23 |
| `TICKETON_LOOKAHEAD_DAYS` | `7` | Горизонт сеансов, максимум 31 день |
| `TICKETON_ADJACENT_SEATS` | `2` | Размер соседнего блока по умолчанию; чат может выбрать от 1 до 6 мест |
| `TICKETON_REQUEST_TIMEOUT_MS` | `15000` | Timeout одного запроса к сайту |
| `TICKETON_MAX_SESSIONS_PER_RUN` | `300` | Предохранитель числа карт зала за tick |
| `TICKETON_MANUAL_MAX_SESSIONS` | `30` | Предохранитель числа карт зала за ручную проверку, не выше лимита tick |
| `TICKETON_CATALOG_TTL_MS` | `300000` | In-memory TTL каталогов, минимум 30 секунд |
| `TICKETON_MENU_PAGE_SIZE` | `8` | Кнопок с пунктами на страницу, максимум 20 |

Интеграция использует публичные, но внутренние интерфейсы сайта, поэтому изменение Ticketon может потребовать обновления путей или нормализации ответа. Ошибка одного фильма или сеанса логируется и не останавливает остальные проверки.
