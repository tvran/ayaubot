# Монитор мест Ticketon

Команда `/kino` открывает inline-клавиатуру с фильмами из раздела [«Кино» Ticketon для Астаны](https://ticketon.kz/astana/cinema) и кинотеатрами города. Список наблюдения общий для чата: любой участник может включить или выключить фильм и фильтр кинотеатра. `✅` означает, что пункт уже выбран. Если кинотеатры не выбраны, проверяются все кинотеатры Астаны. Кнопка `🔎 Проверить сейчас` запускает проверку только для текущего чата и присылает отдельную сводку.

Сервис передаёт каталогу Ticketon фильтры `city=astana` и `category=cinema`, а затем повторно проверяет главную категорию каждого результата. События из разделов концертов, театров, спорта и других категорий в меню и scheduler не попадают.

## Компоненты

- `src/kino/client.js` читает публичные JSON API Ticketon и нормализует фильмы, сеансы, сектора и места;
- `src/kino/seats.js` ищет последовательные свободные места;
- `src/kino/service.js` строит меню, переключает подписки и запускает проверки;
- `src/worker/index.js` запускает scheduler только в постоянном worker;
- `migrations/007_ticketon_cinema_monitor.sql` создаёт отдельные Ticketon-подписки и delivery markers.

Ticketon IDs не смешиваются с сохранёнными IDs прежнего провайдера: после миграции фильмы и кинотеатры нужно выбрать заново через `/kino`. Каталог меню кешируется в памяти worker на пять минут. Клавиатура разбивается на страницы по восемь пунктов, а выбранные позиции, исчезнувшие из текущей афиши, всё равно показываются, чтобы их можно было удалить.

## Проверка мест

Scheduler запускается сразу при старте worker, затем раз в `TICKETON_CHECK_INTERVAL_MS` (по умолчанию один час). Он загружает сеансы выбранных фильмов на ближайшие семь дней, исключает прошедшие, закрытые для продажи и, если задан фильтр, чужие кинотеатры. За один tick обрабатывается не более `TICKETON_MAX_SESSIONS_PER_RUN` подходящих сеансов.

Ручная проверка использует те же правила поиска и delivery markers, поэтому уже отправленный сеанс не создаёт повторное уведомление. При этом итоговая сводка отдельно показывает число проверенных сеансов, сеансов с хорошими местами и новых уведомлений. Один ручной запуск читает не более `TICKETON_MANUAL_MAX_SESSIONS` карт зала и выполняется в heavy-очереди worker.

Клиент соединяет статическую геометрию сектора с динамическим наличием по ID места. Свободным считается место с `count > 0`; сектора без нумерованных мест пропускаются. Ряды сортируются по числовому номеру, а при текстовой метке — по координате `y`. Проверяется половина зала с более высокими номерами рядов, включая средний ряд в зале с нечётным числом рядов. Подходящий блок содержит минимум `TICKETON_ADJACENT_SEATS` последовательных номеров без большого физического разрыва по координатам карты.

Когда блок найден, сервис атомарно вставляет `(chat_id, session_id)` в `ticketon_notifications`. Поэтому один сеанс оповещается один раз даже при нескольких worker replicas. При временной ошибке Telegram marker удаляется и следующий tick может повторить отправку. Уведомление содержит прямую Ticketon-ссылку на схему выбранного сеанса и передаётся общему обработчику `/all`: он проверяет сохранённых участников чата и добавляет безопасные mention entities.

## Доступ к карте зала

Афиша, сеансы, геометрия зала и динамическое наличие мест читаются через публичные read-only endpoints `api-gw.ticketon.kz`. Клиент не отправляет `Authorization`, bearer-токен или cookie. Для мониторинга не нужно хранить пользовательскую сессию Ticketon.

## Настройки

| Переменная | Default | Назначение |
| --- | --- | --- |
| `TICKETON_MONITOR_ENABLED` | `true` | `false` отключает scheduler, не удаляя подписки |
| `TICKETON_BASE_URL` | `https://ticketon.kz` | Базовый адрес ссылок в уведомлениях |
| `TICKETON_API_URL` | `https://api-gw.ticketon.kz` | Базовый адрес публичного JSON API |
| `TICKETON_CITY_ID` | `1` | ID Астаны в API сеансов |
| `TICKETON_CITY_CODE` | `astana` | Код Астаны в каталоге и фильтре кинотеатров |
| `TICKETON_TIME_ZONE` | `Asia/Almaty` | Локальная дата афиши и отсечение прошедших сеансов |
| `TICKETON_CHECK_INTERVAL_MS` | `3600000` | Интервал, минимум 60 секунд |
| `TICKETON_LOOKAHEAD_DAYS` | `7` | Горизонт сеансов, максимум 31 день |
| `TICKETON_ADJACENT_SEATS` | `2` | Минимальный соседний блок, от 2 до 12 мест |
| `TICKETON_REQUEST_TIMEOUT_MS` | `15000` | Timeout одного запроса к сайту |
| `TICKETON_MAX_SESSIONS_PER_RUN` | `300` | Предохранитель числа карт зала за tick |
| `TICKETON_MANUAL_MAX_SESSIONS` | `30` | Предохранитель числа карт зала за ручную проверку, не выше лимита tick |
| `TICKETON_CATALOG_TTL_MS` | `300000` | In-memory TTL каталогов, минимум 30 секунд |
| `TICKETON_MENU_PAGE_SIZE` | `8` | Кнопок с пунктами на страницу, максимум 20 |

Интеграция использует публичные, но внутренние интерфейсы сайта, поэтому изменение Ticketon может потребовать обновления путей или нормализации ответа. Ошибка одного фильма или сеанса логируется и не останавливает остальные проверки.
